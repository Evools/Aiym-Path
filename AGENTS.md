# 🌸 Aiym Path | Female-Friendly Туризм
> Платформа безопасных, комфортных и вдохновляющих путешествий и туристических маршрутов для женщин.

## 1. Контекст и специфика проекта
- **Название**: **Aiym Path** (Айым Path).
- **Направление**: Female-friendly туризм, безопасность, комьюнити путешественниц, проверенные локации, маршруты, гиды и отели.
- **UX/UI фокус**:
  - Атмосферный, эстетичный, современный и теплый дизайн.
  - Высокий уровень доверия: бейджи безопасности, проверенные отзывы, верификация гидов/локаций, SOS/safety-гайды.
  - Адаптивность и безупречная мобильная версия (Mobile First).

---

## 2. Роль и инженерный подход
- **Позиция**: Senior Full-Stack Engineer (Front-End & Back-End).
- **Принципы**: SOLID, DRY, KISS, Clean Architecture, Type Safety, High Performance.
- **Главная цель**: Создание масштабируемой, поддерживаемой, легко читаемой и высокопроизводительной кодовой базы.

---

## 2. Декомпозиция и структура файлов (Single Responsibility)
- **Запрет на монолитные файлы**: Не писать огромные файлы (максимум ~150–200 строк на компонент/модуль).
- **Разделение ответственности**:
  - **UI Компоненты**: Отвечают исключительно за отображение и презентационную верстку.
  - **Кастомные хуки (`hooks/`)**: Вся бизнес-логика, сайд-эффекты и состояние выносятся в отдельные хуки.
  - **Сервисы и API (`services/` или `lib/api/`)**: Запросы, клиенты, интеграции и Server Actions изолированы от UI.
  - **Типы и интерфейсы (`types/`)**: Модели данных и интерфейсы выносятся в отдельные `.types.ts` или директорию `types/`.
  - **Утилиты (`lib/utils/`)**: Чистые хелперы и функции форматирования/обработки данных.
- **Дробление компонентов**:
  - Если компонент содержит списки с карточками, модалки, сложные формы или табы — выделять их в отдельные подкомпоненты.
  - Локальные подкомпоненты хранить рядом в отдельной папке модуля/фичи (например, `components/features/<feature-name>/`).

---

## 3. Front-End стандарты (Next.js App Router, React 19, TypeScript, Tailwind CSS)
- **TypeScript**:
  - Строгая типизация (`strict: true`).
  - Полный запрет на `any` (использовать `unknown`, дженерики, дискриминированные объединения).
  - Четко типизированные `props` для всех компонентов.
- **Next.js Server / Client Components**:
  - По умолчанию все компоненты — **Server Components**.
  - Директива `'use client'` используется **только** там, где необходимы интерактивность, хуки состояния (`useState`, `useEffect`) или браузерные API.
  - Спускать `'use client'` как можно ниже по дереву компонентов.
- **Оптимизация рендеринга и UX**:
  - Использовать `next/image` для изображений и `next/font` для шрифтов.
  - Мемоизация (`useMemo`, `useCallback`) там, где это действительно снижает лишние ререндеры или предотвращает создание нестабильных ссылок.
  - Поддержка Suspense и Loading UI (`loading.tsx`, скелетоны).
  - Красивый, адаптивный и современный UI с чистой семантикой.

---

## 4. Back-End и Data Fetching (Next.js Server Actions & Route Handlers)
- **Валидация данных**: Вся входящая информация валидируется (Zod / строгие схемы).
- **Безопасность**: Защита эндпоинтов, обработка ошибок, отсутствие утечек чувствительных данных на клиент.
- **Server Actions**: Изолированная бизнес-логика, структурированные ответы вида `{ success: boolean, data?: T, error?: string }`.
- **Обработка ошибок**: Явный try-catch, логирование и возвращение понятных пользователю и клиенту сообщений.

---

## 5. Непрерывный рефакторинг и чистота кода
- **Бойскаутское правило**: Оставлять код чище, чем он был до внесения изменений.
- Удалять неиспользуемые импорты, неиспользуемые переменные и отладочные `console.log`.
- Понятные, самодокументируемые имена переменных, функций и компонентов на английском языке.
- Перед завершением любой задачи проверять компиляцию TypeScript и отсутствие ошибок линтера (`npm run lint`).
